# 教师验收与评分工具

本目录为 Lab1-Lab7 提供统一的教师评分入口。它不复制 `labN-solution` 的实现代码，也不把看到 `[LabN] PASS` 等同于完成实验。教师需要同时结合自动测试、代码审查和学生解释形成评分证据。

## 立即使用

直接打开：

```text
docs/teacher-grading/index.html
```

页面完全离线运行，不调用网络接口。评分草稿保存在当前浏览器的 `localStorage`，教师可导出 Markdown 或 JSON。JSON 可在另一台设备上导入继续评阅。

## 与 solution 的边界

| 内容 | `labN-solution` | 本工具 |
|---|---|---|
| 正确实现代码 | 提供 | 不提供 |
| 实现过程说明 | 提供 | 只引用检查位置 |
| 自动测试结果 | 作为参考实现证据 | 作为学生提交的一类证据 |
| 分项评分 | 不负责 | 提供 100 分量表 |
| 常见错误与扣分 | 部分说明 | 提供一致的评分建议 |
| 口试 | 不负责 | 提供问题与回答要点 |
| 成绩记录 | 不负责 | 可保存、导入、导出和打印 |

## 评分原则

每个实验总分 100 分，由五类证据组成：

1. 核心数据结构或入口状态。
2. 核心机制实现。
3. 错误处理、安全边界或下一层机制。
4. 自动测试、QEMU 运行和前置实验回归。
5. 代码解释、设计取舍和口试。

页面会在下列情况下给出建议封顶，但教师可以关闭封顶开关并根据课程规定人工决定：

- 目标内核构建失败：建议不超过 39 分。
- QEMU 端到端验收失败：建议不超过 59 分。
- 修改禁止变更的基础设施或测试判定：建议不超过 59 分并人工复核。

## 自动验收与人工验收的边界

自动测试可以证明：

- 工程能够格式化、构建和通过静态检查。
- 主机单元测试覆盖的纯算法行为正确。
- QEMU 输出出现指定 marker 和稳定顺序。
- starter 没有提前输出当前实验 PASS。

自动测试不能单独证明：

- 学生没有硬编码输出或绕过测试。
- TrapFrame、TaskContext 等汇编/Rust 布局完全合理。
- unsafe 使用满足安全前提。
- 页表权限遵循最小权限原则。
- 学生真正理解实现而不是只复制代码。

因此教师必须检查页面列出的代码位置，并至少抽查一道口试题。

## Starter 防泄露检查

对每个 `labN-starter`，教师至少确认：

- `scripts/test-labN.ps1 -ExpectIncomplete` 能正常结束。
- 输出包含当前实验 TODO。
- 输出不包含当前实验 PASS。
- starter 仍保留前置实验能力。
- TODO 对应真实代码缺口，而不只是隐藏或删除 PASS 字符串。
- 不包含 solution 的完整函数体、答案注释或可直接复制的补丁。

## 数据与隐私

- 页面不上传评分记录。
- 导出的 JSON 可能包含学生姓名和教师评语，提交仓库前应脱敏。
- 不建议把真实成绩文件提交到公开 Git 仓库。
- 需要共享评分记录时，优先使用匿名编号代替姓名和学号。

## 开发验证

语法检查和核心逻辑测试：

```powershell
node --check docs/teacher-grading/rubric-data.js
node --check docs/teacher-grading/grading-core.js
node --check docs/teacher-grading/app.js
node --test docs/teacher-grading/grading-core.test.js
```

核心测试验证：七套量表均为 100 分、分值边界、建议封顶、日志 marker 解析、Markdown 导出和 JSON 协议校验。
