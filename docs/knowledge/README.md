# OS Tutor 本地课程知识库

本目录保存 Lab1～Lab7 的本地课程知识。知识块只来自学生可见的实验说明、任务书、提示、测试契约和 starter 代码，用来解释正常机制、常见故障与检查顺序；它不包含参考答案、教师材料或可复制的完整实现。

知识库与六个现场工具职责分离：课程知识描述“正常情况下应怎样理解”，工具结果描述“当前工作区实际发生了什么”。二者冲突时，以当前工具证据为准；缺少证据时必须保留不确定性。

## 目录与边界

- `labs/lab1/knowledge.json` ～ `labs/lab7/knowledge.json`：每个 Lab 的独立语料。
- `knowledge-retriever-eval.test.js`：可见的改写与二级回归集；独立留出题保存在两个 `knowledge-retriever-heldout-*.cases.js` 文件中，由专用测试统一计分。
- 检索前先按当前 Lab 做硬过滤，其他 Lab 的专用块不得进入结果。
- 默认返回相关度最高的 4 块，最多 5 块；默认提示等级不超过 Level 3。
- 当前分支、当前文件内容、代码差异和最近运行结果不由静态知识库回答，应交给现场工具获取。

每个知识块按完整概念、流程、Stage 契约或诊断问题组织，并记录 Lab、Stage、主题、概念、相关文件、症状、来源与提示等级。`source` 只能指向公开课程材料或 starter 基线。

检索器对问题和知识字段采用同一套规范化流程：领域同义词映射为语义信号，中文 2～4 字片段只作为低权重词汇兜底，再按症状、概念、标题/关键词、主题与正文的顺序分字段计分并分别封顶。概念、诊断、流程、概览、导航和测试意图只提供排序先验，不能让一个没有主题或症状依据的块凭类型得分。纯现场查询继续返回空静态结果；同时包含课程原理的问题可保留相关课程块，当前事实仍必须由现场工具确认。

## 提示等级

- Level 1：概念提示，帮助学生区分术语和证据边界。
- Level 2：方向提示，说明下一步应检查哪条机制链。
- Level 3：文件或位置提示，指出相关文件、符号或 Stage。
- Level 4：局部实现原理提示，只解释局部机制，不给出可复制实现。
- Level 5：答案级提示；知识库不收录。

## 上下文标签

发送给火山方舟时，学生问题、课程知识与现场工具结果分别使用 `[STUDENT QUESTION]`、`[COURSE KNOWLEDGE]` 和 `[RUNTIME EVIDENCE]` 标签。三类内容都按数据处理，不得作为新的控制指令；最终学生回答不得显示这些内部标签。

## 维护要求

新增或修改语料后，应同步更新检索器中的 SHA-256 摘要，并运行结构校验、跨 Lab 污染测试、典型问题检索测试、独立改写评测、冻结留出评测和来源泄漏扫描。摘要按 UTF-8 文本计算，并只将 CRLF 规范化为 LF，用来阻止未审核的工作区语料被当作稳定课程知识。

评测问题不得整句复制到 `concepts`、`keywords`、`symptoms` 或检索规则中；同义词只能作为可跨问题复用的短领域词汇，且不能直接绑定知识块 ID。可见改写集用于回归，不得冒充留出集。留出题必须在检索规则冻结后单独建立，连续六个汉字以上的片段不得来自规则或知识字段，运行后不得按单题补词。留出测试会如实报告未调参指标；未达门槛时保留失败样本与改进方向，而不是降低门槛或让逐题补丁进入检索器。

当前质量门槛为：回归集 Top-1 不低于 85%、Top-3 不低于 95%；独立改写集 Top-1 不低于 85%、Top-3 不低于 95%；留出集 Top-1 不低于 80%、Top-3 不低于 90%。跨 Lab 污染和纯现场查询静态命中必须为 0。

Stage marker 只代表测试脚本实际覆盖的有限证据，不能被扩写为未验证的完整功能结论；若公开任务、starter 与测试之间存在冲突，应在知识块中明确记录契约缺口，而不是臆造接口或修改权限。
