# Lab6：用户态与系统调用

## 实验简介

本实验引入用户态程序和系统调用，让学生理解内核如何为用户程序提供服务。

## 学习目标

- 理解 U-mode 与 S-mode 的边界。
- 理解 `ecall`、系统调用号、参数和返回值。
- 能运行最小用户程序并返回内核。

## 前置知识

trap、任务管理、地址空间、ABI。

## 前置实验

Lab5：任务管理与协作式调度。

## 涉及模块

规划模块为 `syscall` 和 `user`。具体 crate、目录和函数待 P0 架构确定后补充。

## 学生需要完成的任务

待 P0 架构确定后补充具体函数和 TODO 标记。

## Starter Code 边界

Starter code 应提供最小用户程序构建框架和系统调用号约定，分发逻辑留给学生。

## 参考实现边界

参考实现只实现最小输出、退出和让出 CPU，不引入文件系统。

## 自动测试设计

规划中：用户程序输出稳定 token，内核记录退出码，最终输出 `[lab6] PASS`。

## QEMU 预期输出

规划中，建议包含 `[lab6] start`、用户程序输出和 `[lab6] PASS`。

## 验收标准

- 至少一个用户程序可运行。
- 最小系统调用路径可用。
- 错误系统调用有明确返回或诊断。

## 常见错误

- `ecall` 返回地址处理错误。
- 用户指针未校验。
- 返回值寄存器约定错误。
- 用户栈或入口地址配置错误。

## 思考题

- 为什么用户程序不能直接访问所有内核函数？
- 系统调用接口为什么要保持稳定？
