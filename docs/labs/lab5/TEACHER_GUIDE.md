# Lab5 教师指南

## 课程定位

Lab5 用来讲清楚“任务上下文”和“协作式调度”的最小闭环。它不是完整进程系统，也不是抢占式调度器。

建议课时：2 次课或 1 次课加 1 次实验课。

## 课堂讲授重点

- 为什么任务需要独立栈。
- TCB 中保存哪些状态。
- Ready、Running、Exited 三种状态如何转换。
- `yield` 为什么必须主动调用。
- `__switch` 为什么只保存 callee-saved 寄存器。

## 三个任务的验收方法

| 任务 | 验收命令 | 重点观察 |
|---|---|---|
| 任务一 | `scripts/test-lab5.ps1 -Stage 1` | 是否输出 `[Lab5-T1] PASS` |
| 任务二 | `scripts/test-lab5.ps1 -Stage 2` | 是否输出 `[Lab5-T2] PASS`，并能轮转选择 Ready 任务 |
| 任务三 | `scripts/test-lab5.ps1 -Stage 3` | 是否出现 A/B/C 交替输出和 `[Lab5] PASS` |

## 学生容易卡住的位置

- 任务入口函数不能普通返回，必须走退出路径。
- `next_scan` 更新错误会破坏轮转顺序。
- `__switch` 保存和恢复寄存器偏移不一致会导致 QEMU 崩溃或超时。
- 把 Exited 任务重新调度，导致输出重复或死循环。

## 如何演示

1. 先在 `lab5-starter` 运行 `scripts/test-lab5.ps1 -ExpectIncomplete`，说明 starter 可构建但未完成。
2. 切到 `lab5-solution`，依次运行 Stage 1、Stage 2、Stage 3。
3. 展示 `switch.S`，只讲 `ra/sp/s0..s11` 的保存恢复，不扩展到完整 trap frame。

## 判断是否直接复制答案

可以要求学生解释：

- 为什么 `fetch_next` 不应每次从 0 开始。
- 为什么 `yield_now` 要先把当前任务改回 Ready。
- 为什么 `__switch` 最后用 `ret`。
- 为什么本实验不支持抢占式调度。

如果学生能独立解释这些点，通常说明不是机械复制。

## 可选扩展任务

- 添加任务优先级，但仍保持协作式。
- 添加任务运行次数统计。
- 讨论时钟中断抢占需要哪些额外机制。
- 讨论用户态任务和系统调用如何改变调度器边界。

## 评分建议

- 任务一：25%
- 任务二：30%
- 任务三：35%
- 代码可读性和实验报告：10%

建议不要把抢占式调度作为基础必做内容；它适合作为优秀学生的扩展题。
